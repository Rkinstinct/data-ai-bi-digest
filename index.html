לא מצאתי פרסום חדש מהיום ששווה להעביר כחדשה. שלושה רעיונות שלא שלחתי, עם גיל המקור גלוי:

1️⃣ לצבוע תאי שורה במטריצה לפי *הערך בעמודה האחרונה המוצגת*. SQLBI בונה Visual Calculation שרואה את תוכן המטריצה כטבלת `ROWS COLUMNS`, מוצא את השנה האחרונה ואת המותג בעל המכירות המרביות בה, ומחזיר צבע לכל תא של אותו מותג גם בשנים האחרות. זו שכבת *עיצוב הוויזואל*, לא מדד עסקי במודל: כשמשכפלים ויזואל, אפשר להתאים את בחירת הציר בלי להוסיף עוד מדדי צבע למודל. להתחלה: Matrix עם Brand בשורות, Year בעמודות, Sales Amount בערכים; להוסיף פונקציית DAX קטנה שמוצאת את הזוכה בשנה האחרונה וחישוב חזותי שמחזיר `Yellow`, ואז להחיל Conditional Formatting מסוג Field value על *תאי המדד*. כותרות השורה עצמן אינן נתמכות בעיצוב מותנה. מאמר SQLBI מאפריל 2026, מתקדם ודורש תמיכת UDF/Visual Calculations בגרסת הארגון. https://www.sqlbi.com/articles/using-visual-calculations-to-highlight-an-entire-row/ https://learn.microsoft.com/en-us/power-bi/create-reports/desktop-conditional-table-formatting

2️⃣ סכום כולל נכון דורש לקבע את גרעין הכלל העסקי, לא לסכום את השורות שמוצגות כרגע. במאמר של SQLBI ממודל ייצור, לכל מתכון יחס סוכר אחר; `AVERAGE` של היחסים בתא ה-Total נראה סביר אך אינו נותן כמות סוכר נכונה. הפתרון: `SUMMARIZE` מייצר שורה לכל מתכון, `SUMX` מכפיל בתוך כל מתכון את כמות המים שלו ביחס שלו ורק אז מחבר. זה חי *בשכבת המדד/המודל*, בניגוד לפריט העיצוב הראשון. ביום־יום דפוס כזה מונע סיכומי תקציב, שערים ותעריפים שגויים כשמחליפים ציר או עושים Drill. להתחלה: לזהות את גרעין המקור, גרעין הכלל וגרעין התצוגה ולבדוק Total בכמה מבני מטריצה. מאמר ספטמבר 2026; שווה לימוד, לא מוצר חדש. https://www.sqlbi.com/articles/writing-dax-at-the-correct-granularity/

3️⃣ לנסות שתי דרכי תיקון על *אותו הקשר שיחה* ב-Claude Code באמצעות `/fork`. הפקודה מעתיקה את השיחה עד אותו רגע לסשן רקע עצמאי, כולל הקשר הפרויקט, ומאפשרת לתת לענף אחד ניסוי על מבנה הדוח ובענף שני להמשיך פתרון שמרני. זה לא Worktree בפני עצמו: Worktree מבודד קבצים, בעוד `/fork` משכפל *את ההקשר השיחתי*; הסשן החדש עובר לעותק עבודה מבודד לפני עריכת קבצים לפי התיעוד. מתחילים מתוך שיחה עם תכנית ובדיקות שכבר גובשו, מקלידים `/fork נסה פתרון חלופי למדד מבלי לפרוס`, ואז פותחים `claude agents` כדי לראות מה מתקדם. עדיין צריך להשוות diff ולמזג ידנית. תיעוד רשמי; ההתנהגות הזו דורשת לפחות v2.1.212 ו-Agent View פעיל, ויש חריגים כשאי אפשר לרשת דגלי השקה מסוימים. זה כלי עבודה על *סשנים*, לא גרסת מודל ולא פריסה אוטומטית. https://code.claude.com/docs/en/agent-view

1️⃣ עמודת שם חודש שמתרגמת את עצמה לכל קורא של אותו דוח. ב-Power BI אפשר להגדיר לעמודה מחושבת `Expression Context = User Context`: היא לא נשמרת ב-Import בזמן רענון, אלא מחושבת בזמן שאילתא לפי הקשר המשתמש. שילוב `FORMAT` עם `USERCULTURE()` מחזיר למשל שם חודש בשפת הקורא. ביום־יום צוות יכול להחזיק דוח אחד לקהלים בכמה שפות בלי לשכפל טבלת תאריכים או לבנות מדד נפרד לכל תווית. חשוב לשמור זהות מספרית מאחורי תווית מתורגמת באמצעות Group By Columns על Month Number, אחרת בחירת סלייסר המבוססת על המחרוזת עלולה לא להישמר במעבר בין שפות. זו *שכבת המודל המוצגת בדוח*, לעומת מדד טקסט של אתמול שחי בתא המטריצה; עמודה כזו נגישה לצירים ולסלייסרים אבל עלולה לייקר שאילתות. להתחלה: עמודת `FORMAT ( DATE ( 2020, 'Date'[Month Number], 1 ), "mmmm", USERCULTURE() )`, שינוי המאפיין ב-Desktop, ואז בדיקה עם שני משתמשים ושפות. SQLBI מציין Preview במאי 2026; תיעוד Microsoft מאשר את המאפיין אך לא אימתתי זמינות בגרסה הארגונית שלכם.

לא מצאתי היום חידוש טרי שעובר את רף הערך. שני מדריכים שלא שלחתי קודם, עם תאריך המקור מפורש:

1️⃣ יתרת הזמנות פתוחות כ-Visual Calculation עם יתרת פתיחה מהמודל. SQLBI מראה ש-`RUNNINGSUM` על המטריצה מחבר את מספר ההזמנות שהתקבלו ומנכה את אלה שסופקו, כשהחישוב רץ על הטבלה הווירטואלית שכבר אוגדה לפי חודש במקום לסרוק שוב כל עסקה בכל תא. המלכודת: אם חותכים בסלייסר את החודשים הראשונים, החישוב החזותי לא רואה את ההיסטוריה שלפניהם ומציג יתרה שגויה; מוסיפים מדד DAX במודל שמחזיר את יתרת הפתיחה שלפני התאריך הראשון שנבחר. ביום־יום זה בונה מטריצת backlog שקלה לקריאה ולתחזוקה. להתחלה: שני מדדי בסיס Received ו-Delivered, אחריהם שתי צבירות `RUNNINGSUM`, ואז הפרש בתוספת יתרת פתיחה. השכבה היא *הוויזואל*, בעוד מדד יתרת הפתיחה חי *במודל*. חשוב: SQLBI מציג בהמשך גם פתרון DAX טהור שהיה מהיר יותר במדגם שלו. זה מדריך מנובמבר 2024, לא פיצ'ר חדש ולא הבטחת ביצועים לכל מודל.

https://www.sqlbi.com/articles/computing-open-orders-with-visual-calculations-in-dax/

2️⃣ פקודת `/goal` ב-Claude Code: להגדיר מצב סיום מדיד במקום לבקש שוב ושוב "תמשיך". בסוף כל סבב מודל בקרה קטן בודק את תנאי הסיום מול מה שהשיחה כבר הראתה; אם אינו מתקיים, Claude ממשיך לסבב הבא. הוא לא מריץ בדיקות בעצמו ולא קורא קבצים בנפרד, לכן צריך לדרוש ש-Claude יריץ את הבדיקות ויביא את הפלט לשיחה. דוגמה לצוות BI: "קובצי PBIP נשמרים, בדיקות אימות המבנה מסתיימות בקוד 0, לא השתנו קובצי נתוני אמת, או עצור אחרי 12 סבבים". ביום־יום זה מועיל לרפקטורינג שחוזר על תיקון-בדיקה, לא להחלטות מוצר פתוחות. מתחילים ב-`/goal ...`, בודקים מצב עם `/goal`, ועוצרים ידנית ב-`/goal clear`. זו יכולת מתועדת של Claude Code ממאי 2026, *שכבת בקרת סשן*, לא בידוד הקבצים של Worktree ששלחתי אתמול ולא TASKS.md בלבד. היא אינה משנה הרשאות, עלולה להיחסם כש-hooks מנוטרלים בארגון, ועולה שימוש מודלים לכל סבב.

1️⃣ פרטי עסקה בתוך שורה אחת במטריצה, בלי לפתוח היררכיה ובלי ויזואל נוסף. SQLBI מראה איך מדד טקסט מאחד כמה מאפיינים לעמודת Details אחת. המנגנון: ISINSCOPE מגביל את המדד לשורת מזהה העסקה, ו-CONCATENATEX עובר על רשימת קטעי טקסט אחרי סינון הריקים. אם הפרטים מגיעים מטבלת ממד בכיוון סינון הפוך, הדוגמה המלאה משתמשת ב-CROSSFILTER מקומי בתוך CALCULATE, ולא משנה את כל קשרי המודל. ביום־יום זה חוסך עמודות צרות, גלילה אופקית וקליקים על שורות לצורך פרטי הקשר. להתחלה: להוסיף Order Number לשורות מטריצה, ליצור מדד שמציג למשל מטבע ושער, ולבדוק סיכומי ביניים ועסקאות עם כמה שורות פריטים. זה טריק ברמת *הדוח/המדד*, לא SVG או ויזואל מותאם, ולא עוד Calculated Column קבועה. מדריך מומחה של SQLBI מינואר 2026, לא פיצ'ר חדש.

2️⃣ שתי עבודות Claude Code על אותו פרויקט בלי שיכתבו זו על זו. Worktree הוא עותק עבודה נפרד עם ענף Git משלו והיסטוריית repo משותפת. מפעילים `claude --worktree report-a` ו-`claude --worktree report-b` בחלונות שונים, נותנים לכל אחד משימה נפרדת, בודקים diff ומכניסים את השינויים הרצויים לענף הראשי בבקרת אדם. ב-PBIP זה שימושי כשאחד משנה הגדרת דוח והשני בוחן מדדים, בתנאי שהקבצים ב-Git והסביבה נבנית מחדש בעותק. לעומת subagents, המחלקים משימות בתוך שיחה, Worktrees מבודדים *קבצים וענפים* בין שיחות. התיעוד גם מציע `isolation: worktree` ל-subagent שעורך קבצים. יכולת מתועדת רשמית של Claude Code, דורשת Git ותמיכה בגרסה המקומית; לא להניח שהיא מחוברת למאגר הארגוני או להעתיק סודות לעותקים.

🔹 לצבוע את ערכי כל שורת המטריצה לפי הזוכה בעמודה האחרונה

נניח שמותגים בשורות, שנים בעמודות ו-`Sales Amount` בערכים. רוצים להדגיש את המותג עם המכירות הגבוהות בשנה האחרונה שמוצגת, גם בתאים של שנים קודמות. הצביעה היא על *תאי הערכים*, לא על כותרת השורה.

1. הכינו Matrix עם `Product[Brand]` בשורות, `Date[Year]` בעמודות ומדד `Sales Amount` בערכים. במודל שתומך ב-DAX UDF צרו את הפונקציה הבאה:

RowHeaderOfLastCol =
    (
        matrix : TABLE,
        colHeader : COLUMNREF,
        rowHeader : COLUMNREF,
        valueExpr : EXPR
    ) =>
    VAR LastColHeader = MAXX ( matrix, colHeader )
    VAR RowsInLastCol =
        FILTER ( matrix, colHeader = LastColHeader )
    VAR MaxValueInLastCol = MAXX ( RowsInLastCol, valueExpr )
    VAR WinningRows =
        FILTER ( RowsInLastCol, valueExpr = MaxValueInLastCol )
    RETURN
        SELECTCOLUMNS ( WinningRows, "rowHeader", rowHeader )

2. הוסיפו למטריצה Visual Calculation. הוא מרחיב את הקשר התא לכל טבלת השורות והעמודות, מוצא את המותגים שזכו בעמודה האחרונה, ואז מחזיר צבע לתאי המותג הנוכחי:

Row Color =
VAR BestBrands =
    CALCULATETABLE (
        CALCULATETABLE (
            RowHeaderOfLastCol (
                ROWS COLUMNS, [Year], [Brand], [Sales Amount]
            ),
            EXPAND ( ROWS COLUMNS )
        ),
        COLLAPSEALL ( ROWS COLUMNS )
    )
VAR CurrentBrand = [Brand]
RETURN
    IF ( CurrentBrand IN BestBrands, "#FFF2B2" )

3. בעיצוב המותנה של `Sales Amount`, בחרו Background color → Field value → `Row Color`. בדקו שכשמסננים שנים, הזוכה נקבע לפי השנה האחרונה *המוצגת*. אם המהדורה שלכם לא מקבלת תוצאה טקסטואלית בחישוב חזותי, הגדירו את Data Format שלו ל-Text. התיעוד של Microsoft מגביל עיצוב מותנה לערכים, לא לכותרות השורות.

🔹 יתרת הזמנות פתוחות ב-Matrix בלי לחשב את כל ההיסטוריה מחדש בכל תא

הטריק הוא לשלב חישוב חזותי מהיר על החודשים *המוצגים* עם מדד במודל שמביא את יתרת הפתיחה לפני החלון שנבחר. בלי יתרת הפתיחה, סלייסר שמתחיל בינואר מציג בינואר יתרה כאילו לא היו הזמנות בדצמבר.

1. צרו טבלת Date רציפה. קשר פעיל בין `'Date'[Date]` לבין `Sales[Order Date]`, וקשר לא פעיל אל `Sales[Delivery Date]`. הניחו מזהה הזמנה `Sales[Order Number]` ותאריך אספקה לכל הזמנה שסופקה.

2. צרו מדדי בסיס במודל:

Orders Received = DISTINCTCOUNT ( Sales[Order Number] )

Orders Delivered =
CALCULATE (
    [Orders Received],
    USERELATIONSHIP ( Sales[Delivery Date], 'Date'[Date] )
)

Received RT =
CALCULATE (
    [Orders Received],
    'Date'[Date] <= MAX ( 'Date'[Date] )
)

Delivered RT =
CALCULATE (
    [Orders Delivered],
    'Date'[Date] <= MAX ( 'Date'[Date] )
)

Starting Open Orders =
CALCULATE (
    VAR FirstDateInVisual = MIN ( 'Date'[Date] )
    RETURN
        CALCULATE (
            [Received RT] - [Delivered RT],
            'Date'[Date] < FirstDateInVisual
        ),
    ALLSELECTED ( 'Date' )
)

3. הוסיפו למטריצה חודש מ-Date בשורות ואת שלושת המדדים `Orders Received`, `Orders Delivered` ו-`Starting Open Orders` לערכים. בתפריט New visual calculation צרו את שלושת החישובים הבאים, כל אחד בנפרד:

Received RT Visual = RUNNINGSUM ( [Orders Received], ROWS )

Delivered RT Visual = RUNNINGSUM ( [Orders Delivered], ROWS )

Open Orders Visual =
    [Starting Open Orders]

🔹 פרטי עסקה בעמודה אחת של מטריצה, בלי להרחיב עוד רמות

כשמוסיפים Currency ו-Exchange Rate כעמודות במטריצה, היא נמתחת לרוחב. במקום זה אפשר להוסיף מדד טקסט לצד המדדים המספריים. הוא מופיע רק בשורת העסקה, לא בסיכום.

1. שימו `Sales[Order Number]` בשורות של Matrix. הניחו שבטבלת Sales קיימות גם העמודות `Currency Code` ו-`Exchange Rate`, ושבכל עסקה יש ערך יחיד לכל אחת מהן.

2. צרו את המדד הבא; התאימו שמות עמודות למודל:

Transaction Details =
IF (
    ISINSCOPE ( Sales[Order Number] )
        && HASONEVALUE ( Sales[Order Number] ),
    VAR Code = SELECTEDVALUE ( Sales[Currency Code] )
    VAR Rate = SELECTEDVALUE ( Sales[Exchange Rate] )
    RETURN
        CONCATENATEX (
            FILTER (
                {
                    IF ( NOT ISBLANK ( Code ), "מטבע: " & Code ),
                    IF ( NOT ISBLANK ( Rate ), "שער: " & FORMAT ( Rate, "0.000" ) )
                },
                NOT ISBLANK ( [Value] )
            ),
            [Value],
            " | "
        )
)

3. גררו את המדד ל-Values של המטריצה. בשורת עסקה עם מטבע ושער תקבלו למשל `מטבע: EUR | שער: 1.085`; בשורת סיכום הוא ריק. בדקו עסקה עם כמה שורות פריטים: אם יש יותר מערך מטבע/שער אחד, SELECTEDVALUE יחזיר ריק במקום להציג פרט שגוי. למידע שמגיע מטבלת Customer, צריך לטפל גם בכיוון הסינון; המאמר מדגים זאת עם CROSSFILTER מקומי.
