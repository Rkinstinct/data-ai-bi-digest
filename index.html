1️⃣ חדש: לפני דירוג לקוחות, מגדירים את החוזה של המדד מאמר SQLBI מ-5.10 מדגים למה "כתוב לי דירוג לקוחות" אינו מפרט מספיק. צריך להגדיר מי מתחרה בדירוג, אילו מסננים נשמרים, האם המכירות מצטברות, איך שוברים שוויון ומה עושים כששם אחד מייצג שני מפתחות לקוח. בדוגמה, הקבוצה כוללת קונים היסטוריים עד סוף התקופה; הדירוג מבוסס על מכירות מצטברות, ושוויון נשבר לפי מפתח לקוח עולה. הקוד נכתב רק אחרי שהכללים נשמרו בקובץ ונקראו חזרה. ביום-יום: שינוי עסקי מתחיל בעדכון הכללים, ולא בניחוש מה התכוון מדד ישן. לניסוי, קחו מדד דירוג קיים ובקשו מהעוזר לזהות שאלות פתוחות, לשמור חוזה ולבנות מקרי בדיקה לפני שינוי DAX. בדקו במיוחד שמות כפולים, לקוח היסטורי בלי מכירות בתקופה ו-Total. שכבה: משמעות עסקית ובדיקות במודל, לא כלי פריסה. זו שיטת עבודה של SQLBI, לא פיצ'ר Power BI; גם מחברי המאמר אומרים שהמדד לדוגמה דורש אימות לפני ייצור. https://www.sqlbi.com/articles/understanding-dax-contracts-when-using-ai/

2️⃣ בחירת YTD ו-PY יחד יכולה לקבל משמעות מפורשת חזרה נבחרת מ-1.10. בחירה מרובה בקבוצת חישוב אינה שרשור אוטומטי של הפריטים. הביטוי multipleOrEmptySelectionExpression בודק את קבוצת הבחירה ומנתב את הצירוף המדויק YTD+PY אל פריט PYTD. כך סלייסר אחד יכול להציע צירופים מוגדרים בלי לשכפל מדדים או ויזואלים. לניסוי: בקבוצת זמן קיימת מגדירים את הביטוי דרך TMDL ומשווים את שתי הבחירות לתוצאה של PYTD לבדו. בודקים גם צירוף לא נתמך וסינון שמחזיר אפס פריטים. הסרת הסינון אינה "empty selection"; היא שייכת להתנהגות noSelectionExpression. שכבה: לוגיקת הסלייסר במודל. משלים את חוזה המדד, לא מחליף אותו. מדריך SQLBI מסמן Preview בזמן פרסומו ביוני 2025 ודורש תאימות 1605 לפחות; אין כאן קביעה לגבי סטטוס היכולת בגרסה הארגונית שלכם. https://www.sqlbi.com/articles/controlling-empty-or-multiple-selections-in-calculation-groups/ https://powerbi.microsoft.com/en-us/blog/deep-dive-into-selection-expressions-for-calculation-groups/

3️⃣ ממוצע נע בתוך Small multiples, בלי להוסיף מדד למודל חזרה נבחרת מ-2.10, עם אימות נוסף מהמקור הרשמי. חישוב חזותי פועל על הנתונים שכבר הוכנסו לוויזואל. אפשר למשל להוסיף MOVINGAVERAGE למדד המכירות בגרף קו שמפוצל למדינות. זה שימושי כשיש הרשאת עריכת דוח אבל לא רוצים לשנות מודל משותף. לניסוי: ציר זמן ממויין, מדד מכירות ו-Small multiples של מדינה; מוסיפים חישוב חזותי ומשווים חלון של שלוש נקודות בפאנל אחד ידנית. שלוש נקודות אינן בהכרח שלושה ימים כשחסרים תאריכים. בתיעוד, ROWPAGES הוא הציר של הפאנלים: חישוב לאורך הזמן וחישוב בין מדינות אינם אותה תנועה. שכבה: הוויזואל, בשונה מקבוצת החישוב שפועלת במודל. סיכום ספטמבר הרשמי מציין GA לתמיכה בחישובים חזותיים ב-Small multiples; צריך גרסת Desktop מתאימה. https://learn.microsoft.com/en-us/power-bi/transform-model/desktop-visual-calculations-overview https://community.fabric.microsoft.com/blog/fbc_pbiupdatesblog/power-bi-september-2026-feature-summary/5325831

4️⃣ מעקב בסשן פתוח או עבודה מתוזמנת בענן: לא אותו כלי חזרה משולבת מ-2–3.10. פקודת /loop מריצה פרומפט שוב ושוב בסשן המקומי, עם הקבצים והרשאות הסשן. היא מתאימה למעקב קצר אחרי בדיקה או build; המחשב והסשן צריכים להיות פעילים, והמשימה פגה לאחר שבעה ימים. משימות שלא פגו ניתנות לשחזור באמצעות --resume. לעומתה, Routines מריצות סשן בענן על clone טרי של הריפו, בלי מחשב פתוח ובלי הקבצים המקומיים. הן מתאימות לעבודה מתמשכת, אבל מחייבות התאמה של סביבת הענן והחיבורים לארגון. הן פועלות באופן אוטונומי, ולכן לא כדאי להתחיל מפרומפט שנותן הרשאה פתוחה לשינויים. לניסוי מקומי: התחילו בלולאה לקריאה ודיווח בלבד, עם מרווח מפורש, ועצרו ב-Esc. אל תשתמשו בפרומפט התחזוקה המובנה בלי להבין מה הוא עשוי לעשות. שכבה: תזמור העבודה, לא DAX ולא שכבת הדוח. שני המנגנונים מתועדים רשמית; ל-API של Routines יש מגבלות research preview המפורטות בתיעוד. https://code.claude.com/docs/en/scheduled-tasks https://code.claude.com/docs/en/routines

בחירה בשני פריטים באותה קבוצת חישוב אינה מפעילה אותם ברצף. אפשר להגדיר שהצירוף המדויק מפעיל PYTD, וכל צירוף אחר מטופל במפורש.

1. במודל ניסוי עם טבלת תאריכים יומית תקינה, התחילו מקבוצת חישוב בשם Time Intelligence ועמודת בחירה Name. הגדירו שלושה פריטים:

לפריט YTD: ```DAX CALCULATE ( SELECTEDMEASURE (), DATESYTD ( 'Date'[Date] ) ) ```

לפריט PY: ```DAX CALCULATE ( SELECTEDMEASURE (), SAMEPERIODLASTYEAR ( 'Date'[Date] ) ) ```

לפריט PYTD: ```DAX CALCULATE ( SELECTEDMEASURE (), SAMEPERIODLASTYEAR ( DATESYTD ( 'Date'[Date] ) ) ) ```

2. ב-TMDL View גררו את טבלת הקבוצה לסקריפט. בתוך calculationGroup הוסיפו את המאפיין multipleOrEmptySelectionExpression, עם הביטוי הבא. שמרו את הפריטים הקיימים והשתמשו במבנה הרב-שורי של TMDL כפי שמודגם במדריך:

VAR Chosen = VALUES ( 'Time Intelligence'[Name] )
VAR Expected = { "YTD", "PY" }
VAR IsExactPair =
    COUNTROWS ( Chosen ) = 2
        && COUNTROWS ( INTERSECT ( Chosen, Expected ) ) = 2
RETURN
    IF (
        IsExactPair,
        CALCULATE (
            SELECTEDMEASURE (),
            'Time Intelligence'[Name] = "PYTD"
        ),
        ERROR ( "Unsupported time selection" )
    )

3. החילו את השינוי והוסיפו סלייסר של Name שמאפשר בחירה מרובה. השוו YTD+PY ל-PYTD לבדו, גם במדד מכירות וגם במדד נוסף, כולל Total.

לפריט YTD: ```DAX CALCULATE ( SELECTEDMEASURE (), DATESYTD ( 'Date'[Date] ) ) ```

לפריט PY: ```DAX CALCULATE ( SELECTEDMEASURE (), SAMEPERIODLASTYEAR ( 'Date'[Date] ) ) ```

לפריט PYTD: ```DAX CALCULATE ( SELECTEDMEASURE (), SAMEPERIODLASTYEAR ( DATESYTD ( 'Date'[Date] ) ) ) ```

2. פתחו את TMDL View וגררו אליו את טבלת הקבוצה כדי לקבל את הסקריפט הקיים. בתוך בלוק `calculationGroup`, הוסיפו את המאפיין הבא לצד הפריטים, לא במקומם:

multipleOrEmptySelectionExpression =
    VAR Chosen = VALUES ( 'Time Intelligence'[Name] )
    VAR Expected = { "YTD", "PY" }
    VAR IsExactPair =
        COUNTROWS ( Chosen ) = 2
            && COUNTROWS ( INTERSECT ( Chosen, Expected ) ) = 2
    RETURN
        IF (
            IsExactPair,
            CALCULATE (
                SELECTEDMEASURE (),
                'Time Intelligence'[Name] = "PYTD"
            ),
            ERROR ( "Unsupported time selection" )
        )

🔹 לצבוע את ערכי כל שורת המטריצה לפי הזוכה בעמודה האחרונה

נניח שמותגים בשורות, שנים בעמודות ו-`Sales Amount` בערכים. רוצים להדגיש את המותג עם המכירות הגבוהות בשנה האחרונה שמוצגת, גם בתאים של שנים קודמות. הצביעה היא על *תאי הערכים*, לא על כותרת השורה.

1. הכינו Matrix עם `Product[Brand]` בשורות, `Date[Year]` בעמודות ומדד `Sales Amount` בערכים. במודל שתומך ב-DAX UDF צרו את הפונקציה הבאה:

RowHeaderOfLastCol =
    (
        matrix : TABLE,
        colHeader : COLUMNREF,
        rowHeader : COLUMNREF,
        valueExpr : EXPR
    ) =>
    VAR LastColHeader = MAXX ( matrix, colHeader )
    VAR RowsInLastCol =
        FILTER ( matrix, colHeader = LastColHeader )
    VAR MaxValueInLastCol = MAXX ( RowsInLastCol, valueExpr )
    VAR WinningRows =
        FILTER ( RowsInLastCol, valueExpr = MaxValueInLastCol )
    RETURN
        SELECTCOLUMNS ( WinningRows, "rowHeader", rowHeader )

2. הוסיפו למטריצה Visual Calculation. הוא מרחיב את הקשר התא לכל טבלת השורות והעמודות, מוצא את המותגים שזכו בעמודה האחרונה, ואז מחזיר צבע לתאי המותג הנוכחי:

Row Color =
VAR BestBrands =
    CALCULATETABLE (
        CALCULATETABLE (
            RowHeaderOfLastCol (
                ROWS COLUMNS, [Year], [Brand], [Sales Amount]
            ),
            EXPAND ( ROWS COLUMNS )
        ),
        COLLAPSEALL ( ROWS COLUMNS )
    )
VAR CurrentBrand = [Brand]
RETURN
    IF ( CurrentBrand IN BestBrands, "#FFF2B2" )

3. בעיצוב המותנה של `Sales Amount`, בחרו Background color → Field value → `Row Color`. בדקו שכשמסננים שנים, הזוכה נקבע לפי השנה האחרונה *המוצגת*. אם המהדורה שלכם לא מקבלת תוצאה טקסטואלית בחישוב חזותי, הגדירו את Data Format שלו ל-Text. התיעוד של Microsoft מגביל עיצוב מותנה לערכים, לא לכותרות השורות.

Orders Received = DISTINCTCOUNT ( Sales[Order Number] )

Orders Delivered =

)

Received RT =
CALCULATE (
    [Orders Received],
    'Date'[Date] <= MAX ( 'Date'[Date] )
)

CALCULATE (
    [Orders Delivered],
    'Date'[Date] <= MAX ( 'Date'[Date] )

🔹 פרטי עסקה בעמודה אחת של מטריצה, בלי להרחיב עוד רמות

כשמוסיפים Currency ו-Exchange Rate כעמודות במטריצה, היא נמתחת לרוחב. במקום זה אפשר להוסיף מדד טקסט לצד המדדים המספריים. הוא מופיע רק בשורת העסקה, לא בסיכום.

1. שימו `Sales[Order Number]` בשורות של Matrix. הניחו שבטבלת Sales קיימות גם העמודות `Currency Code` ו-`Exchange Rate`, ושבכל עסקה יש ערך יחיד לכל אחת מהן.

2. צרו את המדד הבא; התאימו שמות עמודות למודל:

Transaction Details =
IF (
    ISINSCOPE ( Sales[Order Number] )
        && HASONEVALUE ( Sales[Order Number] ),
    VAR Code = SELECTEDVALUE ( Sales[Currency Code] )
    VAR Rate = SELECTEDVALUE ( Sales[Exchange Rate] )
    RETURN
        CONCATENATEX (
            FILTER (
                {
                    IF ( NOT ISBLANK ( Code ), "מטבע: " & Code ),
                    IF ( NOT ISBLANK ( Rate ), "שער: " & FORMAT ( Rate, "0.000" ) )
                },
                NOT ISBLANK ( [Value] )
            ),
            [Value],
            " | "
        )
)

3. גררו את המדד ל-Values של המטריצה. בשורת עסקה עם מטבע ושער תקבלו למשל `מטבע: EUR | שער: 1.085`; בשורת סיכום הוא ריק. בדקו עסקה עם כמה שורות פריטים: אם יש יותר מערך מטבע/שער אחד, SELECTEDVALUE יחזיר ריק במקום להציג פרט שגוי. למידע שמגיע מטבלת Customer, צריך לטפל גם בכיוון הסינון; המאמר מדגים זאת עם CROSSFILTER מקומי.
